OpenCloud Radio — layouts

Ten directions for the internet radio player, and a tuned version of the first (11), the one it implements. Same content and the same OpenCloud colour roles in every one, so the only variable is the layout.

Colours are the real light and dark role tokens from the OpenCloud design system and server theme, so these should sit correctly next to Files. Every mockup follows the system theme and carries a Light / Dark / System switch in the bottom right. Where a spectrum analyser appears it is drawn as a placeholder in 04 and 09, the two that reserve real space for it; 11 draws it.

01 Three pane

Lists on the left, a station table in the middle, a player bar along the bottom.

Works because
Reads as a native OpenCloud screen and needs no explanation. The list rail is always visible, so moving between lists is one click.
Costs you
The least distinctive of the ten. The table gives each station the same weight, which makes a 60-station list hard to scan.

02 Files-native with details panel

Breadcrumb, row list and a right-hand details panel, borrowing the Files layout directly.

Works because
Users already know this shape. The details panel is the natural home for the stream address, format and last-played time without a modal.
Costs you
Two side panels plus a player bar leaves a narrow middle column on small screens. The breadcrumb implies folder navigation the app does not actually offer.
Open full size

03 Tile wall

Stations as cards in a responsive grid, with group filters as chips above.

Works because
Logos carry recognition better than text, and the grid reflows to any width without a separate mobile design.
Costs you
Low density — about twelve stations per screen against forty in the table layouts. Without logos the tiles are mostly empty space.
Open full size

04 Tuner

A now-playing stage over a horizontal band of stations, with tick marks suggesting a dial.

Works because
The only layout with a point of view about what radio is. The stage has room for the spectrum analyser without redesigning anything.
Costs you
Horizontal scrolling hides stations and is awkward with a keyboard. The dial metaphor stops paying off past about twenty stations.
Open full size

05 Hero and column

A large now-playing panel with the station list as a narrow column on the right.

Works because
Puts the thing that is actually happening at the centre. Calm, and it works well as a screen left open on a second monitor.
Costs you
Editing and reordering have nowhere to live, so both need a modal. Half the screen is given to four lines of text.
Open full size

06 Dense table

Full-width data table with the stream address visible, a docked player, keyboard hints.

Works because
Highest density of the ten and the only one that shows the stream URL in the list, which is what you need when a station stops working. Tabs replace the rail and reclaim the width.
Costs you
It looks like a database table rather than a music player. The URL column pushes the minimum comfortable width up.
Open full size

07 Master and detail editor

Station list on the left, a full editing form on the right, shown here in an error state.

Works because
Adding and fixing stations is the work this app actually involves, and this is the only layout that treats it as a first-class screen rather than a modal. Blocked-station explanations have room to be useful.
Costs you
The detail pane is mostly empty when you are only listening. Optimises for the setup task over the everyday one.
Open full size

08 Search first

One search field over everything, with a small floating player card.

Works because
Scales past a thousand stations without a scrollbar, and the same field accepts a pasted stream address, so adding a station and finding one are the same gesture.
Costs you
Nothing is visible until you type, which hides the library and makes browsing impossible. Reordering a list has no home here at all.
Open full size

09 Console

A player console strip across the top with a dedicated analyser panel, two list panes below.

Works because
Designs the spectrum in from the start rather than bolting it on, and two visible lists make dragging a station between them possible.
Costs you
The console takes a fixed 170 px of height whether or not anything is playing. Two panes need real width to work.
Open full size

10 Narrow and touch

The single-column layout at phone width, with a bottom sheet player and a floating add button.

Works because
The only one that answers what happens below about 700 px, which every other layout still needs. Large touch targets, one-handed transport controls.
Costs you
Not a desktop design — this is the companion to whichever of the others is chosen, not an alternative to them.
Open full size

11 Three pane, tuned

Mockup 01 with a resizable list divider, a columns preference, and a taller player carrying the spectrum above the transport row.

Works because
The divider defaults to 268 px, which fits the longest list name without truncation, clamps to 208-520 px, and stores the value in localStorage. Drag it, arrow-key it, or double-click to reset. The analyser strip is 84 px, one and a half times the 56 px transport row below it. Visible columns — including the full stream address — are chosen from the Columns menu and stored per device. Theme follows the OpenCloud setting unless it is overridden in the switch.
Costs you
The player now takes 141 px of vertical space whether or not anything is playing, which is about three station rows.
